# 月老 Skill (yuelao_skill)

把抖音情感/红娘博主的口播经验，通过「爬取 → 语音转文字 → 多级蒸馏」提炼成结构化知识，
最终封装成一个可对**择偶画像**进行评估、打分与建议的 AI Skill。

---

## 1. 项目目标

情感/婚恋博主在短视频里积累了大量关于「什么样的人适合什么样的择偶标准、哪些信号是红旗/绿旗、
不同画像之间如何匹配」的经验性判断。这些知识零散地分布在成百上千条口播里，无法直接使用。

本项目要做的是把这些**隐性的、口语化的、重复且噪声很大的经验**，逐级提炼成
**显性的、结构化的、可复用的评估框架**，并最终落地为一个 Skill：

> 输入一个人的择偶画像（年龄/职业/收入/性格/诉求等）→ 输出对其择偶预期合理性的评估、
> 匹配建议、潜在风险点。

## 3. 各阶段详细设计

### 阶段 1 + 2：数据采集 与 语音转文字（已实现）

实现文件：`data/crawl_douyin.py`

**流程：**
1. `fetch_account_posts()` — 调用抖音 Web API `aweme/v1/web/aweme/post/` 分页拉取指定博主
   （`SEC_USER_ID`）的作品列表，最多 `MAX_VIDEOS`（默认 150）条。通过 `TikTokDownloader`
   的 **ABogus 签名器** 生成 `a_bogus` 参数过抖音风控。
2. `parse_video_info()` — 解析每条作品，按分辨率/FPS/码率挑最优播放地址，跳过图集（无视频）。
3. `download_video()` — httpx 流式下载 mp4 到 `douyin_output/temp/`。
4. `extract_audio()` — ffmpeg 抽取音频为 mp3。
5. `transcribe_audio()` — 本地 `faster-whisper`（默认 `large-v3` / CUDA / float16）转中文文本。
6. 结果追加写入 `douyin_output/transcriptions.csv`，转写后删除临时视频/音频文件节省空间。

**输出 CSV 字段：** `序号, 作品ID, 发布时间, 时长(秒), 视频描述, 语音转写文本`

**依赖：**
- `httpx`、`faster_whisper`
- 系统需安装 `ffmpeg`
- `TikTokDownloader`（仅用其 `src.encrypt.aBogus.ABogus`）
- GPU（CUDA）推荐；无 GPU 可设 `WHISPER_DEVICE=cpu` + `WHISPER_COMPUTE=int8`

**配置（环境变量）：**
- `WHISPER_MODEL`（默认 `large-v3`）
- `WHISPER_DEVICE`（默认 `cuda`）
- `WHISPER_COMPUTE`（默认 `float16`）

> ⚠️ **安全提醒**：当前 `crawl_douyin.py` 第 30 行硬编码了真实抖音 Cookie（含 `sessionid`
> 等登录凭证，等同账号密码）。务必在进版本库/分享前移到 `.env` 或环境变量，避免盗号。

### 阶段 3：多级蒸馏（核心，决定质量上限）

原始转写（`aoye.csv` 等，~2000+ 条）特点：**口语化、无标点、说话人不分、含大量引流/娱乐噪声、
Whisper 错字多**。但其主体是**直播连麦点评**——连麦者自报择偶画像，博主当场打颜值分、
"画个像"（开出建议的目标对象画像）、给诊断建议，并夹带通用经验金句。

因此蒸馏不走抽象的"观点单元"路线，而是**面向连麦案例做结构化抽取**：把每条口播抽成
**两类数据**——
- **案例（cases）**：一个连麦者的完整画像 + 博主的颜值分析 / 诊断 / 建议 / 开出的目标画像
- **通用经验（general_insights）**：可脱离具体人独立成立的规律/金句（带适用条件、倾向、溯源）

数据量小（估计 1000~1500 条案例），**质量优先**：可负担强模型多遍处理 + 全程人工抽检。

```
原始转写(~2000条)
   │  3a · L1 结构化抽取(逐条：先分类→只对连麦案例/混合抽 cases+insights)
   ▼
结构化记录(JSONL, 每字段带原文quote + stated/inferred)
   │  3b · 归一化(自由文本→受控档位, 形成可检索的 segment key, 去重)
   ▼
归一化案例库 + 维度字典
   │  3c · L2 分层规律提炼(按画像segment聚类 → 每类的策略/落差模式, 共识加权)
   ▼
分层策略库(供阶段4升华为评估框架)
```

**3a — L1 全量结构化抽取**
- Prompt 已落地：`prompt/structured_extraction.md`（含内容分类、双表 schema、博主黑话词典、
  Whisper 错听纠正、颜值打分锚点、完整示例）。
- 用强模型（Opus/Sonnet）低温度跑全量；**两遍法**：第一遍抽取 → 第二遍自检（校验每个 value 的
  `quote` 是否真出现在原文、数字有无脑补），不一致标 `needs_review`。
- 内容分类先行：`引流广告 / 娱乐打分` 只留摘要不抽案例，从源头去噪。
- **质量关卡**：人工抽检 ~50 条核对准确率，回调 prompt。
- 产物：`distill/l1_records.jsonl`（cases + insights）+ 分类统计。

**3b — 归一化（让案例可检索）**
- 把抽出的原始值映射成**受控词表档位**：年龄→年龄段、收入→收入档、资产→标准 A 级、
  城市→层级、学历→档（双非/211/985/C9/海本…）、颜值→按锚点的档。这套归一字段即后续检索的
  **画像 segment key**；原始值 + `quote` 一并保留（溯源）。
- 去重近似重复案例。
- 产物：`distill/cases_normalized.jsonl`、`distill/维度字典.json`。

**3c — L2 分层聚类 + 规律提炼（"策略/规律"在此诞生）**
- 按 segment 给 cases 分组，对每个**样本充足的 segment**做 LLM reduce，提炼：
  典型诉求 / 博主典型诊断模式 / 通用建议 / **期待 vs 博主开像的落差模式** / 红旗绿旗，
  并记 **支持案例 ID + 频次（共识强度）+ 支持博主数**。
- **质量关卡**：每个 segment 的提炼**人工审一遍**（这是知识资产，必须 curated，不能现编）。
- 产物：`distill/l2_segments.json`。

**关键设计原则：**
- **溯源**：每条规律能追回支撑它的案例 ID / 视频。
- **共识加权 + 分歧并存**：频次与博主数量作权重，避免一个极端案例被当成普遍规律；矛盾观点不强行统一。
- **杀手锏——预期 vs 现实落差**：每条 case 同时含「连麦者期待画像」与「博主开出画像」，
  可直接学出"某类人想要的 vs 现实能匹配到的"之间的 gap，正是阶段5"预期合理性评估"的依据。
- 蒸馏 prompt 与中间产物全部落盘、可复跑、可增量（新增视频只跑 L1 增量再并入）。

> 注：**"相处经验"维度已砍**——本批数据几乎全是择偶筛选/连麦点评，skill 只保留择偶评估 + 博主建议。

### 阶段 4：知识库构建

把阶段3的策略库升华为 Skill 可直接引用的知识资产。

**4a — L3 评估框架 + rubric（核心知识资产）**
- 从 L2 分层策略升华出可执行评估体系：
  - **维度体系**：颜值红利 / 收入预期合理性 / 资产匹配 / 年龄窗口 / 学历 / 城市 / 家庭结构 / 性格
  - **rubric.json**：每维度的打分锚点 + 权重。锚点逐一定义，例如：
    - 颜值（约10分制，博主实际只用低段）：3-4=普通人 / **5=班级领先（达5即"颜值红利"）** / 6=院花院草 / 7+=明星网红级；注意"自评常偏高"的系统性偏差，以博主实打分为准
    - 年龄窗口：女性约 23-27 为"黄金期"
    - 收入预期合理性、资产匹配等同理定锚
  - **red_flags.md / green_flags.md**：红旗/绿旗信号清单
- **质量关卡**：框架人工精修——skill 的判断力全靠它。
- 产物：`knowledge/framework.md`（人读）+ `knowledge/rubric.json`（机读）+ 红绿旗清单。

**4b — 知识库组装 + 检索**
- 检索语料 `cases_normalized.jsonl` + 精选 few-shot 案例池 `cases.jsonl`。
- 检索机制：**segment 硬过滤（性别/年龄段/城市层级/收入档/资产档/学历档/颜值档）+ 语义 rerank**。
  数据量小，可预计算 embedding，甚至纯结构化过滤即可，不必上重型向量库。
- 产物：`knowledge/` 完整知识库 + 检索索引。


---

### 阶段 5：Skill 封装 + 评测（质量闭环）

最终交付物：一个可被 Claude Code / Agent 调用的 Skill。

**输入（择偶画像）：** 年龄、性别、职业、收入、学历、所在城市、性格特点、
婚恋诉求/对象期望、过往关系等（结构化或自然语言均可）。

**评估流程：** 用户画像 → 归一化 → 定位 segment → 检索 5~10 条相似真实案例 + 该 segment 策略
→ **对照「用户期待 vs 同类博主开像」算落差** → 按 rubric 打分 → 生成报告。

**输出（评估报告）：**
1. 各维度评分 + 总体合理性判断
2. 预期 vs 现实的落差点（哪些诉求偏理想化）
3. 红旗/绿旗信号识别
4. 可执行的调整建议
5. **引用支撑的真实案例 / 视频（溯源）**

**形态：** `SKILL.md`（描述触发条件、输入输出契约、调用 `framework.md`/`rubric.json` 与检索逻辑）。
可纯 prompt 驱动，也可附一段评分计算脚本。

**质量闭环——可量化评测：** 留一批 **held-out 真实案例**当测试集，把连麦者画像喂给 skill，
比对其评估/建议是否与博主真实判断吻合。**我们有 ground truth（真人案例），所以能真正测出 skill 质量**，
据此迭代框架与检索——这是本项目相对一般经验类 skill 的核心质量优势。

> 注意定位：这是一个**经验参考/启发工具**，不是科学测评或情感操纵工具——
> 输出应是建议性的，并提示用户其经验来源与局限。

---

## 0. 贯穿全程的质量铁律

1. **溯源**：每条规律、每个评分都能追到案例 ID / 视频。
2. **共识加权 + 分歧并存**：频次与博主数量作权重，矛盾观点不强行统一。
3. **人在环中**：3a 抽检、3c 每 segment 审、4a 框架精修——三道人工质量关。
4. **全落盘、可复跑、可增量**：新增视频只跑 L1 增量再并入。
5. **质量优先于速度**：数据量小，宁可强模型多遍 + 人工精修，不追求快速雏形。
